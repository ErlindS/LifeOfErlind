If your SWC needs to store data nonvolatile, it needs a Nv-block it can interact with. This implicates that typically (-> we will see another approach later) there is a 1:1 mapping between SWC data and NvBlockDescriptors. The Nv-block's characteristics need to be configured in accordance to the requirements of the application data it stores.  
The interaction between the SWC and its assigned Nv-blocks can be done via application callbacks, or more recommendable, via service Client/Server-Ports provided by Rte. Using the C/S-Ports allows to trigger NvM Jobs and get informed about their status. However, the data handover to NvM (in case of a write-Job), or from NvM (in case of a read-Job) per default is done implicitly, while the NvM processes the Job. This leads to the necessity to implement synchronization mechanisms between the Application and the NvM.
