In the previous chapter we saw how Software Components interact with each other. Now we will have a look inside of those Software Components. What we need here is code and to execute that code. This is normally done with the help of Runnables. 

**What Are Runnables?**

- Runnables are C-Functions containing the actual implementation.
    - E.g. _void Runnable(void)_
- Runnables might be executed when RTE Events (triggers) occur.
    - E.g. when data is received, a timer expires or by a function call

Atomic Software components contain one or more runnable entities (Runnables) as part of their internal behavior. A runnable entity is the executable unit of a software component.

The SWC LeftDoor contains a runnable which name is RCtLeftDoor. The runnable needs to have an Access Point (AP). The AP is mapped to one or more Data Elements of the Port. So the runnable knows which Data Element is interesting for it. Also a runnable needs to have a trigger. There are different kinds of triggers. In this example there is a periodical trigger set. Every 200ms the runnable will be triggered.

Because of the sending port there is a method generated which lokes like this: Rte_Write_PpDoorState_DeDoorState(localDoorState)

This means:

Write the value of the variable localDoorState to the RTE. The method is autogenerated and shows all needed information. 

Rte_Write (write some value to the RTE)

- PpDoorState (from Port named PpDoorState)
- DeDoorState (to the mapped Data Element named DeDoorState).

The return value of the method is a so called standard return type which gives you information if the action was successful or not. For example in case of success, the return value is RTE_OK.
