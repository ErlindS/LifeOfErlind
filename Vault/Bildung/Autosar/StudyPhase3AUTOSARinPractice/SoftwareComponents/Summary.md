In this Chapter you learned about the SWC. Let's recap the different topics:

### 

**Component Types**

Component types include Composition Component Type, Atomic Component Type, Application Component Type and Service Component Type.  
  
Composition Component Type represents a complex component comprising multiple sub-components, forming higher-level functionality.  
  
Atomic Component Type is a single, indivisible unit of functionality that cannot be further broken down.

Application Component Type focuses on providing specific application-related functionality, tailored to meet application requirements.

Service Component Type represents a service layer module, offering reusable and decoupled services accessible to other components. 

### 

**Runnable Entities**

For runnable entities in software components we discussed various essential elements:

Access points define the entry or exit points through which a runnable entity interacts with the system.

Triggers initiate the execution of a runnable entity.

Port interfaces represent the templates for ports, specifying their properties and behavior.

A port prototype is the actual used port interface with a software component.

Data elements are individual pieces of information exchanged between runnable entities.

Data types describe the format and interpretation of data elements, ensuring consistency in communication.

### 

**Data Types**

Base Types are fundamental data types like booleans, integers and floating-point numbers, providing consistent data representation across microcontroller platforms.

Implementation Data Types (IDT) act as references to Base Types and link them to software components in the development tool.

Application Data Types (ADT) are defined within Software Components (SWC) and represent the logical behavior and semantics of data, abstracted from hardware-specific details.

### 

**Units, Data Constraints & Compu Methods**

Units establish standardized representation of physical quantities for consistent data interpretation.

Data Constraints impose restrictions on valid data values.

Compu Methods enable mappings between logical and physical data representations.
